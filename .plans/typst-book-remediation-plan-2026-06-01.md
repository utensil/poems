## Root Cause Summary

The previous implementation treated "file exists and Typst compiles" as completion. That missed the actual acceptance criteria for a book:

- Typography and page roles are not designed as a coherent system.
- Cover/front matter/appendices/chapter dividers use generic heading styles.
- The cover does not carry the author identity properly.
- `src/postscript.md` is fabricated summary text instead of the real 代后记 article from `main.tex`.
- Other appendix prose is also scaffold-level text rather than editorially settled content.
- `sync-from-cog-land.py` creates random gradient placeholder PNGs for most poems.
- Placeholder prompts are generic, not poem/commentary-derived.
- LaTeX font commands such as `{\textsf 洑}` and `{\textsf 湲}` leaked into Markdown.
- Long poem/commentary pages overflow because split/pagination was not applied broadly enough.
- Some horizontally long poem lines came from source line choices and need source-level rebreaking.
- 年谱 uses heading subsections, causing ugly Chinese heading numbering and bloated outline entries.
- The table of contents includes 年谱 subsection entries, which should not appear.
- Validation does not detect source fabrication, leaked LaTeX commands, placeholders, outline pollution, or page overflow.

## Known Concrete Failures

### Source Fidelity

`src/postscript.md` currently contains short generated prose, not the real article from `main.tex` section:

```text
代后记：在日常里写旧体诗的一点体会
```

This must be replaced by the real article text from `main.tex`, converted carefully to Markdown.

### LaTeX Command Leakage

Current source files containing raw LaTeX commands:

```text
src/poems/压力阴郁/齿轮.md
src/poems/心情与事件/出戏.md
src/poems/云南丽江香格里拉之旅/盘山.md
```

Observed lines:

```text
念执临穴{\textsf 洑}水行，
潮去漩{\textsf 洑}陷泥滩，
崖下江潺{\textsf 湲}，
```

These were originally font fallback hints. They should be stripped to plain characters if the chosen book fonts contain the glyphs:

```text
念执临穴洑水行，
潮去漩洑陷泥滩，
崖下江潺湲，
```

Validation must fail on any remaining raw LaTeX command in Markdown poem text.

### Placeholder Images

Most assets are generated by `common.write_png(...)`, a deterministic colored gradient placeholder. This is unacceptable for final book pages.

Placeholder prompt signature currently found in many files:

```text
Textless literary illustration for a Typst poem book page.
```

Validation must distinguish:

- real generated image with specific prompt sidecar
- explicit temporary placeholder allowed only in a dev/pilot mode
- forbidden generic placeholder in release/final mode

### Overflow

Known overflow/problem cases:

- `十月`: horizontal and vertical overflow; did not happen in earlier sample, so the book pipeline is not applying the same parameters or split behavior.
- `途遇`: vertical overflow; should split across pages after the last full commentary paragraph that fits.
- `启步`: horizontal overflow because a long source line should be rebroken; this may turn into vertical pressure, which should be solved by pagination.
- Many poem pages overflow at the commentary area and bottom.

Validation must not rely on manual PDF inspection.

### Outline/TOC

年谱 currently uses `==` subsections, producing entries like:

```text
十、一、 2011年春
十、二、 2012年春
...
```

年谱 period labels must not be book headings included in the outline. They should be styled body blocks or unnumbered/non-outlined headings. The TOC should include high-level book sections only.

## Required Design System

Before patching individual pages, define a central Typst design system. This should live in a dedicated file:

```text
templates/book-style.typ
```

It should define all fonts, sizes, colors, spacing, and page-role renderers.

### Font Roles

Proposed roles:

```text
cover-title-font
cover-subtitle-font
author-font
chapter-title-font
poem-title-font
poem-body-font
pinyin-font
context-font
commentary-font
prose-heading-font
prose-body-font
```

Initial defaults should be conservative and consistent with the illustrated page prototype:

```text
poem-title-font/body-font: STKaiti or Kaiti SC
commentary/context/prose-font: STFangsong or Zhuque Fangsong
pinyin-font: Kaiti SC
```

The exact choice needs visual testing because the current book mixes fonts inconsistently.

### Book Page Roles

The design must define separate page-role functions:

```text

toc-page(...)
chapter-divider(title, note, count, palette/image?)
illustrated-poem-page(...)
chronology-page(...)

```

Do not let Typst's default `= heading` style drive the final visual design.

Do not use wording like `Typst 插画本` as the author/subtitle slot.

### Front Matter And Appendix Prose

序、凡例、代后记、LLM 说明 must share one coherent prose style:

- consistent title treatment
- consistent body font
- consistent body size
- consistent paragraph leading and spacing
- no generic numbered heading like `一、序` unless explicitly intended

Initial recommendation:

```text

body: 11.5-12pt, FangSong/Zhuque Fangsong
line leading: comfortable book prose, not commentary-compressed
paragraph spacing: moderate
page margins: wider than poem pages, book-like
```

### Chapter Divider Pages

Each poem topic/chapter needs a special cover/divider page matching the illustrated poem page design.

The divider page should include the chapter/topic name. It may include a small note/tagline only if that note exists in the current LaTeX/source material.

Do not use a plain `= 章节名` page.

Do not invent chapter notes or taglines. If the current LaTeX/source material does not provide an additional note for a chapter, render only the chapter title. If a real source note/tagline exists later, render it with deliberate spacing below the title, using a smaller and lighter style.

Current accepted minimal design:

- every chapter has its own cover page
- title is centered vertically and horizontally
- title is large and bold
- long titles must wrap at an intentional place
- `云南丽江香格里拉之旅` needs special handling, likely as:

```text

香格里拉之旅
```

## Source Pipeline Requirements

### No Fabricated Editorial Text

The pipeline may create placeholders only when explicitly labeled as placeholders and excluded from final validation.

Final mode must require:

- real `postscript.md` converted from `main.tex`
- reviewed `fanli.md`
- reviewed `llm-commentary-note.md`
- `preface.md` may be empty or contain a clear `（待补）`, but then the book should either omit 序 or render a deliberate placeholder page only in draft mode

### Real 代后记 Extraction

Implement a source extraction/conversion step:

```text
main.tex section "代后记：在日常里写旧体诗的一点体会" -> src/postscript.md
```

Stop extraction before:

```text
\section{附录：诗词赏析}
```

Convert:

- LaTeX quotes to Chinese/Markdown punctuation where appropriate
- `\begin{quote}...\end{quote}` to Markdown blockquotes
- inline poem examples to blockquotes or verse blocks
- escaped punctuation/commands to plain text where possible

Validation must compare `src/postscript.md` against the extracted source and fail if it is only scaffold text.

### LaTeX Cleaning

Markdown import must normalize inline LaTeX font wrappers:

```text
{\textsf 洑} -> 洑
{\textsf 湲} -> 湲
```

Validation rule:

```text
No raw backslash LaTeX commands are allowed in src/poems/**/*.md body text.
```

If a command cannot be safely stripped, validation must list it as a manual source-fix item.

### Poem Line Rebreaking

Some poems were intentionally stored as longer lines in Markdown, but the illustrated page grid has a maximum comfortable character count.

Implement explicit `layout` metadata per poem when needed:

```yaml
layout:
  line-breaks:
    - "..."
```

or allow reviewed source rebreaking directly in Markdown.

Known case:

```text
启步
```

Do not solve horizontal overflow by compressing the character grid until the page looks unnatural. Rebreak long lines and paginate when needed.

## Illustration Pipeline Requirements

### No Generic Gradients In Final Mode

The current `write_png(...)` placeholder generator must be removed from final builds or gated behind a `--allow-placeholders` dev flag.

Validation must fail final mode if:

- prompt sidecar contains generic placeholder text
- prompt sidecar does not mention the poem title
- prompt sidecar does not mention concrete poem/commentary anchors
- image is known deterministic gradient placeholder

Recommended asset metadata:

```yaml
image-status: generated | reviewed | placeholder
prompt-source: poem-commentary | poem-only | palette-reference
review-status: accepted | needs-regeneration | rejected
```

This can be placed in:

```text
assets/poems/<slug>/illustration.notes.md
```

or a structured YAML sidecar.

## Layout And Overflow Mechanism

### Template-Level Measurement

The illustrated poem template must measure content and split automatically.

Required behavior:

- Measure title+poem+image top block.
- Measure context block.
- Measure commentary paragraphs one by one.
- If next full commentary paragraph does not fit, start a continuation page.
- Do not split inside a paragraph unless explicitly allowed.
- Continuation pages should carry the poem title and `【赏析】续`, not repeat the whole poem unless design calls for it.

The earlier sample behaved better because it used tuned parameters and/or explicit split settings. The book generator must pass those same layout parameters or make them default.

### Typst Assertions

Add a strict build mode that fails when measured content exceeds page bounds.

Examples of assertions:

```text
poem top row width <= content width
poem block height + context + commentary slice height <= available height
image width <= configured image/poem ratio
commentary text box height <= available commentary area
```

Do not rely only on Typst compile success. `place(...)` and clipped boxes can hide overflow.

### Rendered Audit

Add an audit target:

```bash
just audit
```

It should run:

1. `just validate`
2. strict Typst build with layout assertions
3. PDF outline/text audit
4. source-fidelity audit
5. image-placeholder audit

Optional but useful:

```bash
typst compile --root . book.typ build/audit/page-{p}.svg
```

Then parse SVG/PDF text or use debug labels to flag clipped/overflow pages. If full SVG geometry parsing is too expensive, rely on Typst measurement assertions first.

## Validation Plan

Replace "exists and compiles" validation with acceptance-oriented checks.

### Source Checks

`just validate` must fail if:

- `src/postscript.md` does not contain real extracted 代后记 content.
- any `src/poems/**/*.md` body contains raw LaTeX commands.
- any poem body is empty.
- any poem line exceeds the configured max grid width without explicit rebreak metadata.
- commentary status gating is violated.
- `preface.md` is placeholder but the build is final mode.

### Asset Checks

`just validate` must fail if:

- any included final-mode poem uses the deterministic gradient placeholder.
- any prompt sidecar contains generic placeholder wording.
- any prompt sidecar lacks poem-specific content.
- any rejected image is used as active without an explicit accepted fallback note.

### Layout Checks

`just validate` or `just audit` must fail if:

- Typst layout assertions fail.
- generated PDF has fewer/more pages than expected range after stable design baseline.
- `pdftotext` output contains leaked raw commands like `textsf`.
- PDF outline contains 年谱 period headings.
- PDF outline contains internal subsections that should be private to an appendix.
- cover text lacks `宋皿`.
